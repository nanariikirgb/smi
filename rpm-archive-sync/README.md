# RPM Archive Sync

Клиентский мод для Minecraft 1.20.4, Fabric Loader 0.15.11 или новее и Java 17. Fabric API не требуется.

## Сборка и установка

1. Установите JDK 17. Из каталога `rpm-archive-sync` выполните `./gradlew clean build` (Windows: `gradlew.bat clean build`).
2. Скопируйте `build/libs/rpm-archive-sync-1.0.0.jar` в папку `mods` профиля Minecraft 1.20.4 с Fabric.
3. Запустите игру, закройте её и откройте `config/rpm-archive-sync.json`. Укажите адрес сервера в точности как в списке серверов Minecraft, включая порт, если он указан. Регистр адреса не важен. Вставьте общий секрет загрузки, укажите HTTPS-адрес API и включите сбор.

```json
{
  "enabled": true,
  "serverAddress": "minecraft.example.org:25565",
  "endpoint": "https://smi-pearl.vercel.app/api/game-items",
  "token": "ВСТАВЬТЕ_ТОКЕН_ИЗ_VERCEL"
}
```

Сбор выключен по умолчанию. Для отключения сбора и отправки установите `enabled: false` и перезапустите игру. Локальная очередь останется на диске. Изменения конфигурации загружаются при запуске.

## Настройка Vercel

1. В проекте SMI откройте **Settings → Environment Variables**. Добавьте `RPM_ARCHIVE_SYNC_TOKEN` в нужное окружение. Сгенерируйте секрет локально командой `openssl rand -hex 32`. Сохраните то же значение в локальном конфиге мода. Секрет предназначен только для загрузки пакетов.
2. Проверьте существующие переменные Redis `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN` (либо их уже поддерживаемые варианты `KV_REST_API_*` и `STORAG_KV_REST_API_*`), а также `ADMIN_PASSWORD` и `GITHUB_CONTENTS_TOKEN`. Последний используется для чтения актуального community-каталога и публикации решений через существующий механизм GitHub.
3. Разверните изменения. Для POST-запросов админ-панель использует существующий разрешённый источник `https://smi-pearl.vercel.app`. Если разворачиваете панель на другом домене, настройте точный разрешённый origin в `api/admin.js`. Endpoint мода должен быть доступен напрямую по HTTPS без редиректа.
4. Войдите в `/admin.html` и откройте вкладку **Предметы из игры**. Одобрение сохраняет название в `data/community-items.json`. Публичная карточка появится с этим названием, если модель присутствует в ресурс-паке каталога. Отклонение убирает запись из очереди. Повторная загрузка того же сочетания модели и названия её не вернёт.

## Какие данные обрабатываются

Мод проверяет только инвентарь игрока, включая экипировку и вторую руку, на указанном сервере. Проверка выполняется раз в 10 клиентских тиков. Он читает материал, целочисленный `CustomModelData`, пользовательское название и до двух строк Lore. Допустимы цена вида `Стандартная цена: 125.000$` и редкость `[Common]`, `[Uncommon]`, `[Rare]`, `[Epic]`, `[Legendary]`, `[Secret]`, `[Limited]`, `[Event]`, `[Elite]`, `[Season]` или `[RPMPass]`. Названия с признаками адреса электронной почты, URL или длинного номера отфильтровываются. Произвольное название в Minecraft может содержать личный текст, происхождение которого клиент не может надёжно установить. Включайте сбор в окружении, где названия таких предметов задаёт сервер. При модерации проверяйте название перед публикацией.

На диск и в API попадают только разрешённые поля. Мод не отправляет содержимое NBT, серверный адрес, ник, UUID, координаты или данные чата. Он не добавляет рендер и не меняет игровые пакеты, инвентарь или действия игрока.

Очередь и кэш записываются в `config/rpm-archive-outbox-*.json` и привязаны к адресу сервера и URL API. Очередь вмещает до 4096 записей, кэш подтверждённых записей — до 8192. Отдельный поток обрабатывает до 50 записей каждые 60 секунд при наличии очереди и повторяет отправку при сбоях. Доставляются также записи, сохранённые в предыдущем сеансе. API сверяет ключи моделей со статическими метаданными и актуальным community-каталогом, затем добавляет новые записи в Redis одной пакетной операцией.

## Проверка

1. На тестовом сервере получите предмет из ресурс-пака с новым для каталога названием, моделью и допустимой строкой Lore. Дождитесь до 60 секунд и обновите вкладку. Проверьте материал, идентификатор модели, название и Lore.
2. Переложите предмет между слотами и перезапустите Minecraft. После повторной синхронизации проверьте, что у находки одна запись. Предмет с уже известным названием модели не должен появляться в очереди.
3. Временно перекройте доступ клиента к API, получите второй тестовый предмет и проверьте наличие локальной очереди. После восстановления доступа запись должна появиться во вкладке.
4. Проверьте одобрение и отклонение на тестовых предметах. Повторите получение предмета на другом сервере и при `enabled: false`; в этих случаях новые записи не должны добавляться.
