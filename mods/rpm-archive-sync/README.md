# RPM Archive Sync

Клиентский мод для Minecraft Java Edition 1.20.4. Клиент сохраняет находки в локальном кэше. По кнопке «Отправить из кэша» API записывает название, цену и редкость в существующий файл `data/community-items.json` по ключу материала и CustomModelData.

## Установка

1. Установите Fabric Loader для Minecraft 1.20.4 и Java 17. Для экрана настроек добавьте [Mod Menu 9.2.0](https://modrinth.com/mod/modmenu/version/9.2.0) с зависимостями, указанными на странице загрузки.
2. Замените старый RPM Archive Sync в папке `mods` на [rpm-archive-sync-1.2.1.jar](dist/rpm-archive-sync-1.2.1.jar) и запустите игру.
3. В меню игры откройте **Моды → RPM Archive Sync → Настроить** (значок шестерёнки). В поле адресов добавьте нужные домены или IP через запятую. Можно указать порт. По умолчанию используется 25565.
4. Вставьте токен синхронизации, включите сбор и нажмите **Сохранить**. Изменения сразу применяются к текущему подключению. Чтобы отключить сбор, выключите его в том же окне и сохраните. **Отмена** и Esc закрывают окно без сохранения. Пустое поле нового токена оставляет уже сохранённый токен.

Настройки сохраняются в `config/rpm-archive-sync.json`. При обновлении прежний адрес из поля `server` переносится в список `servers` при первом сохранении. Для каждого сервера и адреса API используется отдельная очередь. При необходимости адрес API можно изменить в поле `endpoint` до запуска игры.

## Настройка Vercel

Подключите репозиторий к существующему проекту Vercel, корень проекта — корень репозитория. Разверните ветку с изменениями. Для рабочего сайта перенесите изменения в production-ветку и выполните deployment после настройки переменных в Settings → Environment Variables.

| Переменная | Значение |
| --- | --- |
| `RPM_ARCHIVE_TOKEN` | Отдельный секрет для модов, 32–256 печатных ASCII-символов без пробелов. Можно создать командой `openssl rand -hex 32`. Тот же секрет укажите в локальной конфигурации. |
| `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` | Существующее REST-подключение Redis с правом записи. Также поддерживаются имеющиеся в сайте пары `KV_REST_API_*` и `STORAG_KV_REST_API_*`. |
| `ADMIN_PASSWORD` | Существующий пароль админ-панели, от 16 символов. |
| `GITHUB_CONTENTS_TOKEN` | Серверный токен с доступом Contents: Read and write к nanariikirgb/smi для чтения актуальных названий и автоматической публикации новых игровых названий в main. |

В клиентский файл помещается только RPM_ARCHIVE_TOKEN. Действующая админ-панель принимает POST с origin https://smi-pearl.vercel.app. Для собственного домена обновите проверку origin в api/admin.js и адрес endpoint клиента. При тестировании отдельного развёртывания учитывайте, что действующая публикация админ-панели пишет в main.

## Проверка

1. Зайдите на настроенный сервер и откройте обычный контейнер или дождитесь обновления инвентаря с именованным кастомным предметом. При включении сбора мод один раз читает уже доступный инвентарь. Затем он проверяет обновлённые слоты инвентаря и открытого контейнера. Выбираются предметы с числовым CustomModelData и оформленным буквальным названием. Простые переименования в наковальне пропускаются. Из Lore извлекаются только числовая цена и редкость из фиксированного списка.
2. Пока вы на разрешённом сервере, откройте **Моды → RPM Archive Sync → Настроить → Отправить из кэша**. Кнопка отправляет накопленные находки этого сервера партиями до 32 записей. Находки, появившиеся во время отправки, останутся до следующего нажатия. При изменении настроек сначала нажмите «Сохранить». Публикации видны в истории раздела «Предметы из игры». Уже названные и скрытые модели пропускаются.
3. В кэш попадают только пары материала и CustomModelData из индекса кастомных предметов ресурс-пака RPM. Блоки исключены. После перезапуска игры кэш сохраняется; при ошибке связи нажмите «Отправить из кэша» повторно. Обновите и JAR, и API: новый API отклоняет фоновые отправки старых клиентов. При 401 проверьте совпадение токенов и сохраните новый токен в меню. При 503 проверьте переменные Vercel и доступ к Redis/GitHub.

## Сборка и тесты

С JDK 17 в этой папке запустите `./gradlew clean build` (Windows: `gradlew.bat clean build`). Установочный JAR появится в `build/libs/`. Из корня репозитория можно запустить интеграционные тесты командой `node --test tests/game-items.test.cjs` с Node.js 20+, redis-server и redis-cli в PATH. Тесты используют временный Redis и локальную имитацию GitHub Contents.

После замены ресурс-пака, сборок транспорта или правил исключения моделей запустите из корня `python3 scripts/build-game-model-index.py` и обновите оба сгенерированных индекса, пересоберите JAR и разверните API.
