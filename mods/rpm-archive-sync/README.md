# RPM Archive Sync

Клиентский мод для Minecraft Java Edition 1.20.4. Клиент сохраняет находки в локальном кэше. По кнопке «Отправить из кэша» API создаёт заявки с названием, ценой, коллекцией и редкостью. После одобрения недостающие поля записываются в `data/community-items.json` по ключу материала и CustomModelData.

## Установка

1. Установите Java 17 и Fabric Loader 0.15.11 или новее для Minecraft 1.20.4. Замените старый RPM Archive Sync в папке `mods` на [JAR версии 1.4.0](dist/rpm-archive-sync-1.4.0.jar).
2. Войдите в игру и нажмите **Б** — ту же физическую клавишу, что запятая на английской раскладке. Этот способ работает без дополнительных модов. Настройки также доступны в Mod Menu 9.2.0.
3. Включите сбор и нажмите **Сохранить**. Опубликованный JAR содержит токен для стандартного API. Три адреса по умолчанию — `mc.rpmserver.com`, `fix.rpmserver.ru` и `ru.rpmserver.ru`, порт 25565. При обновлении старого стандартного списка добавятся новые адреса, а `play.rpmserver.com` останется доступным. Личный список и ранее введённый токен имеют приоритет.
4. Выберите **Просмотреть кэш**, чтобы увидеть ожидающие отправки названия, материалы и CustomModelData. Стрелки рядом с адресом переключают сервер. Сохранённые записи доступны и при выключенном сборе. Подтверждённые сайтом записи исчезают из списка. Чтобы передать находки, используйте **Отправить из кэша** на нужном сервере.
5. Для смены клавиши нажмите **Клавиша меню**, затем нужную клавишу и **Сохранить**. Во время выбора Esc отменяет переназначение.

Настройки находятся в `config/rpm-archive-sync.json`. Для каждого сервера и адреса API хранится отдельная очередь. В настройках можно заменить токен или отключить сбор. Изменения применяются сразу после сохранения.

## Настройка Vercel

Подключите репозиторий к существующему проекту Vercel, корень проекта — корень репозитория. Разверните ветку с изменениями. Для рабочего сайта перенесите изменения в production-ветку и выполните deployment после настройки переменных в Settings → Environment Variables.

| Переменная | Значение |
| --- | --- |
| `RPM_ARCHIVE_TOKEN` | Отдельный секрет для модов, 32–256 печатных ASCII-символов без пробелов. Можно создать командой `openssl rand -hex 32`. Значение должно совпадать с токеном клиента. Владелец публичной сборки разрешил распространение её встроенного токена. |
| `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` | Существующее REST-подключение Redis с правом записи. Также поддерживаются имеющиеся в сайте пары `KV_REST_API_*` и `STORAG_KV_REST_API_*`. |
| `ADMIN_PASSWORD` | Существующий пароль админ-панели, от 16 символов. |
| `GITHUB_CONTENTS_TOKEN` | Серверный токен с доступом Contents: Read and write к nanariikirgb/smi для чтения актуальных названий и публикации одобренных игровых данных в main. |

В клиентский файл помещается только RPM_ARCHIVE_TOKEN. Действующая админ-панель принимает POST с origin https://smi-pearl.vercel.app. Для собственного домена обновите проверку origin в api/admin.js и адрес endpoint клиента. При тестировании отдельного развёртывания учитывайте, что одобрение через админ-панель пишет в main. Согласуйте сбор предметов с администрацией игрового сервера.

## Проверка

1. Зайдите на настроенный сервер и откройте обычный контейнер или дождитесь обновления инвентаря с именованным кастомным предметом. При включении сбора мод один раз читает уже доступный инвентарь. Затем он проверяет обновлённые слоты инвентаря и открытого контейнера. Выбираются предметы с числовым CustomModelData и оформленным буквальным названием. Простые переименования в наковальне пропускаются. Из Lore извлекаются числовая цена, название из строки «Коллекция» и редкость из фиксированного списка.
2. Пока вы на разрешённом сервере, откройте **Моды → RPM Archive Sync → Настроить → Отправить из кэша**. Кнопка отправляет накопленные находки этого сервера партиями до 32 записей. Находки, появившиеся во время отправки, останутся до следующего нажатия. При изменении настроек сначала нажмите «Сохранить». Заявки находятся в разделе «Предметы из игры» → «На рассмотрении». Одобренные записи видны в истории. У уже названных моделей обновляются только отсутствующие цена и коллекция. Если в Lore указано лишь одно из этих полей, записывается только оно. Нулевая цена сохраняется как заполненная. Скрытые модели пропускаются.
3. В кэш попадают только пары материала и CustomModelData из индекса кастомных предметов ресурс-пака RPM. Блоки исключены. После перезапуска игры кэш сохраняется; при ошибке связи нажмите «Отправить из кэша» повторно. Обновите и JAR, и API: новый API отклоняет фоновые отправки старых клиентов. При 401 проверьте совпадение токенов и сохраните новый токен в меню. При 503 проверьте переменные Vercel и доступ к Redis/GitHub.

## Сборка и тесты

С JDK 17 в этой папке запустите `./gradlew clean build` (Windows: `gradlew.bat clean build`). Установочный JAR появится в `build/libs/`. Из корня репозитория можно запустить интеграционные тесты командой `node --test tests/game-items.test.cjs` с Node.js 20+, redis-server и redis-cli в PATH. Тесты используют временный Redis и локальную имитацию GitHub Contents.

Для сборки с предустановленным токеном задайте переменную окружения `RPM_ARCHIVE_BUILD_TOKEN`. Workflow RPM Archive Sync читает её из одноимённого секрета GitHub Actions. Если переменная пуста, токен можно ввести в настройках игры.

После замены ресурс-пака, сборок транспорта или правил исключения моделей запустите из корня `python3 scripts/build-game-model-index.py` и обновите оба сгенерированных индекса, пересоберите JAR и разверните API.

Версия 1.3.1 распознаёт `[Ultra]`, `[Collab]` и `[Collection]` как редкость, включая предметы без названия в Lore. На сервере заполняется отсутствующая редкость; уже известная редкость не заменяется. После обновления вновь осмотрите соответствующие предметы и отправьте кэш вручную.
